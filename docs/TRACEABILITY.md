# Requirement traceability matrix

Machine-checked by `npm run verify:trace` (`scripts/verify-traceability.mjs`). For every row, the verifier checks that
each listed implementation file exists. It checks that each «test title» appears as **passed** (`✔`), and never failed,
in the raw logs `docs/evidence/03-unit.txt` (unit) or `docs/evidence/07-e2e.txt` (browser E2E). It checks that
«fw:OK», «audit:OK», «lint:OK» and «ci:OK» resolve to exit 0 in the corresponding evidence files. A `PASS` row needs at least one
verified test. A `BLOCKED` or `PARTIAL` row must name what is NOT TESTED.

Evidence classes: **U** = UNIT TEST · **S** = SIMULATED INTEGRATION (simulator, W3C-API mock, or Chrome with emulated network)
· **St** = STATIC REVIEW/analysis · **R** = REAL BLE INTEGRATION · **P** = PHYSICAL MEASUREMENT. **No row has R or P evidence.**
